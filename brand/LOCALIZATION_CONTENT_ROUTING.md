# Content language and remaining localization acceptance

This isolated donor is based on Spatial candidate #1636 at `d67a7e20fe2aa3d0276620f354587f3678e1aa27`, including the admitted #1640 working catalogs. All twenty catalogs contain the twenty registered strings. Only English is native reviewed. The existing explicit working-preview choice, sensitive English fallback and release gates remain authoritative.

The donor repairs an executable dynamic-content omission: Orb's authenticated request previously omitted response language, its stable request identity omitted language, and speech chose the UI preview language for responses and authored English narration. A single shared transport contract now maps the governed twenty locale IDs to speech tags and text direction. Request language is captured before authentication or provider waits, bound into client and authenticated upstream identities, restricted to that contract, and included in the response schema and model instructions. The server validates matching response metadata and an identical message/caption before publishing deltas. The client checks foreign metadata before displaying deltas. Canonical local fallback stays declared English, including its replay and speech. Orb captions and actions carry their content `lang`/`dir`; long response text can wrap. Narration uses its authored language, defaulting to English, through delayed local fallback. An unsupported declared language retains text and makes no voice submission.

The executable tests use synthetic credentials, database snapshots, model responses and browser voices in process. They cover all twenty client/server transport tags, three RTL languages, authentication/consent no-request cases, unknown tags, language-specific request identity, UI changes during authentication, mismatched or missing foreign metadata, caption mismatch, actual panel attributes/replay, delayed native fallback, cancellation and consent withdrawal. These prove source behavior, not the linguistic quality of generated text. The seven new client/server/panel regressions fail against the unchanged candidate source and pass on this donor.

`Localization Content Routing` checks an exact clean Git head with the canonical frozen pnpm lockfile and Node 22, runs the synthetic and retained suites, and compiles actual frontend and Functions imports. Only a successful received run/attempt and its hashed receipt can establish native source validation. The workflow performs no provider calls and explicitly grants no protected-runtime, translation, voice or release acceptance. A donor's result does not certify a later combined candidate.

Source admission still requires owner review and a new combined-head build/browser result. The complete product is larger than the twenty registered catalog strings: Orb consent/status/error copy, authored narration, private content and other surface copy remain English unless separately specified, cataloged and reviewed. No working catalog has been promoted or invented as a complete product translation.

The first native donor run at `de694b03958332d014a9d9d6233b5f2ac917c5ee` passed all 55 source tests and then exposed an omitted shared-type consumer: Council's authored local fallback needed its English locale. A successor supplies that metadata, preserves Council provider-selection/availability ownership, and strengthens the retained voice/replay contract to require the resolved content locale. The initial native compilation failure is retained history; only a fresh exact-head run can validate the successor.

Final acceptance still needs native reviewers for each prepared non-English locale; approved sensitive/privacy copy; real RTL, expansion, font/script, 200% text and assistive-technology browser/device review; and governed dynamic-output quality checks on the authorized runtime. A model-returned language tag cannot establish that its text is linguistically correct. Real user/private content must retain its source language and governed lineage; this donor does not translate that content. Council, Adam and private person provider routes are separate owners and are unchanged.

Local speech requires an available voice marked `localService` in the captured language; otherwise captions remain available. No device voice inventory or voice identity has been accepted. The unchanged ElevenLabs adapter uses its existing permitted voice/model with per-session consent. The documented `language_code` parameter is not supported by `eleven_multilingual_v2`, so this donor does not add a language-control field that model cannot honor. Authorized provider/model coverage and pronunciation, captions/audio equivalence, identity/rights and device listening remain acceptance work: https://elevenlabs.io/docs/api-reference/text-to-speech/convert.

No main/owner-branch update, merge, deployment, paid request, independent approval or final localization certification is performed by this donor.
