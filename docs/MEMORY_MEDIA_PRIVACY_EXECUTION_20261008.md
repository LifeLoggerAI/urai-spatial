# Owned memory media: source execution boundary

This change adds an authenticated producer for an existing private memory and includes its actual owned bytes in portable memory exports. It is source and synthetic behavioral evidence, not deployed private ingestion, provider erasure, physical-device acceptance or Golden Master certification.

`getMemoryMediaUploadAuthority` and `registerMemoryMedia` require the same current owner, a revocation-checked recent Firebase session, canonical C1 `memory.storage`, the current operational memory policy and revision, and current local/central/permanent deletion fences. C7 `data.export` remains a separate required export authority. The registered attempt is written before the first Storage effect. It binds the configured bucket name, server-derived owner/memory namespace, SHA-256, MIME/size, immutable attempt nonce and create-only object path; ready publication also commits the exact Storage generation. No URL or client-supplied locator is an ownership authority.

Focus mounts the file control only for an existing selected private memory belonging to the signed-in owner. Demo and shared/foreign selections cannot upload. The adapter checks authority before file bytes, uses an operation ID for a response-loss retry, and suppresses stale results after owner/session/selection/unmount cancellation. The callable itself still enforces current authority. An attached receipt is available for export while its memory consent remains current; this source does not add authenticated image/audio/video display or claim a Replay preview.

Exports reject unbound legacy URLs, dangling/orphan sources and unaccounted in-flight attempts. They include generation-pinned bytes after CRC32C, length and SHA-256 verification. READY jobs and receipts retain a hash of the exact media/C1 authority inventory. Their deadline is clamped to the earliest source C1 expiry, and descriptor issuance and each 64 KiB download continuation revalidate C1 separately from C7. Old READY memory packages missing the authority marker are denied.

Deletion and expired-upload reconciliation close each registered create-only attempt with a conditional zero-byte tombstone. Before replacement, a durable receipt ledger records every known binary generation, including the receipt-pinned generation when no live binary remains. Each known prior generation is then explicitly deleted with its exact generation precondition and verified absent through that generation's metadata lookup. A versioned bucket, process interruption, uncertain acknowledgement or retention denial cannot silently become successful cleanup. A fresh authorized deletion or expired-upload reconciliation can resume the known-generation ledger.

The zero-byte marker deliberately remains: deleting it would let a delayed first create-only upload recreate private bytes. Its private metadata contains hashes, the receipt ID and nonce, and a disposal-history hash. Receipts qualify active-generation disposal and this minimal tombstone retention. Provider soft-delete or retention can preserve recoverable data after a successful API delete; this source neither changes bucket policy nor proves permanent erasure or zero residuals. Failed or unverifiable disposal blocks completion.

Implementation bounds remain explicit: uploads are at most 4 MiB; each memory has at most 64 bindings; the existing portable-export document/time/collection/package budgets and the 64 MiB client download limit remain enforced. Exceeding a budget fails closed before READY, rather than producing a silently partial export. Durable multipart/resume and authenticated media preview are separate source capabilities.

The native loaded-Functions emulator cannot execute in this host because its child AF_UNIX listen is rejected with EPERM. Strict compiled handler tests use synthetic SDK/transport fixtures, including both upload/delete orderings, real Node streaming, revocation races, versioned Storage, checksum/generation mismatch and durable retries. They do not substitute for hosted loaded-Functions, protected staging, deployed bucket-policy or live user acceptance.
