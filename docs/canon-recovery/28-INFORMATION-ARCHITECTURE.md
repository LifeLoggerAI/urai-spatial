# URAI Information Architecture

Status: CANONICAL RECOVERY BASELINE

UrAi information is organized by meaning and user ownership rather than conventional app-module silos.

## Primary dimensions

### Time
moments -> days -> seasons -> chapters -> years -> long-horizon legacy.

### Memory
raw capture -> reviewed memory -> Memory Star -> linked context -> Replay -> reflection.

### Meaning
themes, identity, patterns, decisions, achievements, unresolved material.

### Relationships
people, shared moments, trust/context, consented shared spaces.

### Action
goals, milestones, habits, next actions, rituals, future scenarios.

### Place
location snapshots, symbolic places, lived worlds, Ground, place-specific emotional overlays.

### Privacy
local/private cloud/shareable, vaults, permissions, consent, export/delete/revocation.

### System state
loading, forming, unavailable, offline, permission-limited, sample/demo, partial, conflict, failure, recovery.

## Spatial hierarchy

Home
-> Ground OR Ascent
-> Life Map
-> chapter/region/relationship/goal/place
-> Memory Star
-> Focus
-> Replay
-> reflection/related memory/goal/ritual/future branch.

Secondary realms remain linked to this information model rather than becoming isolated databases.

## Search and command

Search/command should resolve across time, people, themes, memories, goals, places and system controls while respecting privacy scope.

## Anti-clutter

Use clustering, semantic zoom, filters, progressive disclosure, LOD, chapter compression and user-controlled layer toggles.
