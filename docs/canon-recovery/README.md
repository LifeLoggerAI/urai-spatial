## Purpose

This package consolidates the recoverable UrAi product universe without pretending that current implementation equals full canon.

It distinguishes:

1. **Locked / current canon** — supported by current source authority, current Drive authority, or explicit founder-established direction.
2. **Current implementation** — what the present runtime or estate repositories implement.
3. **Launch scope** — what the current consumer release must prove.
4. **Post-launch committed work** — known work intentionally beyond the immediate release.
5. **Future canon / research / exploratory lineage** — preserved without silently promoting old experiments into locked canon.
6. **Rejected / superseded lineage** — retained so obsolete visuals and concepts cannot accidentally return.

## Relationship to existing LOCS

The repository already owns a five-tier Layers of Canon Standards (LOCS) hierarchy under `docs/canon/`.

This recovery package does **not** alter Tier-1, Tier-2, Tier-3, Tier-4, or Tier-5 definitions. It is a product-universe/source-reconciliation layer that points back to those governed authorities.

No file in this directory authorizes a canon mutation by itself. A change that actually changes governed canon must follow the existing LOCS migration/review rules.

## Source precedence

When two sources disagree, use this order:

1. live exact-source/runtime authority for implementation truth;
2. explicit current canon/authority documents;
3. current visual/reference authority and exact-head accepted evidence;
4. current repository contracts and manifests;
5. newer explicit founder decisions that clearly supersede earlier direction;
6. historical implementation receipts;
7. historical storyboards/reference art;
8. exploratory scripts/concepts.

Newer is not automatically stronger. A later implementation compromise does not erase long-range canon, and an old ambitious concept does not become canon merely because it exists.
