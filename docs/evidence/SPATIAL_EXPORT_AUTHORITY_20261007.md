# Spatial export authority repair

Date: 2026-10-07
Owner: Spatial operational privacy
Status: source donor; no production or Golden Master certification.

Spatial's own export service uses owner-scoped version2 `privacyPolicy/current`, the `exports` domain, revision-bound export jobs and operation receipts. It is separate from URAI Privacy's canonical `data.export` schema. This repair binds request creation, processing, publication, descriptor issuance and actual delivery to that existing authority. Granted and limited export modes remain supported; missing, denied, paused, malformed or unenforced authority denies. A changed policy revision requires a new export request. Completed legacy jobs without revision, deletion epoch or object-generation binding fail closed.

Deletion requests atomically advance a denial generation and retain distinct pending job markers under the existing server-written `privacyRuntime/exportAuthority` path. Pending or failed legacy deletion jobs also deny. Cancellation/completion removes only its own pending marker, retaining the generation so previously published packages stay invalid after deletion/cancellation. No new consent grant or private-ingestion path is created.

`getExportDownloadUrl` retains its callable name and export/manifest/runtime selection, but returns `requiresAuthorization:true` and a descriptor for `/api/privacy/export/download`. Hosting routes that path to `downloadExportPackage`. Both current recent owner authentication and Auth token revocation are required; future, non-integer or non-number authentication times fail closed. The server rereads the same request/receipt, current consent revision, deletion generation and package deadline after Storage metadata and audits authorization before streaming. Every chunk (at most 64 KiB) repeats current authentication and authority checks; denial destroys the transfer before another chunk. Already emitted bytes cannot be recalled.

Published JSON/manifest/runtime destination generations are pinned for reads. Runtime source generation and SHA remain preserved separately. The Passport and Consent Sanctuary clients send a refreshed Bearer token only to the same application's exact download path, use no redirects/caches/referrer, and save a local Blob only while their existing auth epoch/current owner remains valid. Direct Storage client reads remain denied by existing rules. No new GCS signed URL is issued; old deployed signed URLs retain their original expiry/object-deletion transition and require live release accounting.

Export publication and its receipt commit atomically under current authority. A duplicate worker without a successful claim cannot delete a preparing worker's files. A successful but uncertain publication reply preserves committed bytes/receipt. Late cancellation/deletion is not overwritten by completion or failed-record resurrection.

The current job format bounds each portable collection to 500 documents and intelligence scenarios to 100, with bounded nested inventories. It now reads the next item and fails closed on overflow, including captured-runtime inventory growth during processing. It does not silently publish a truncated ready package. Full pagination beyond these caps is not implemented; an oversized export is explicitly unavailable until a reviewed scalable format/runtime is added.

Verification uses the actual strict-tsc compiled handler with synthetic SDK boundaries, including grant/withdrawal, prior descriptor revocation, current recent/revoked/foreign authentication, storage-await races, audit outage, live chunk continuation, concurrent deletion cancellation, 501-item overflows, uncertain commits, late cancellation, duplicate claims and malformed deletion epochs. Existing private-life-model export/deletion fixtures retain their real inventory/residual assertions and now carry explicit synthetic export authority.

The 38 transport, session and consent-client cases, application runtime typecheck and 10 unchanged static Firestore rules cases pass. No protected-private-helper leaves were changed.
