Status: source donor; no production or Golden Master certification.

It remains separate from URAI Privacy's top-level request/completed-job schema. Delivery additionally requires its current canonical `data.export` C7 grant and matching deletion/consent projection; operational compatibility records cannot independently authorize it. This repair binds request creation, processing, publication, descriptor issuance and actual delivery to that existing authority. Granted and limited export modes remain supported; missing, denied, paused, malformed or unenforced authority denies. A changed policy revision requires a new export request. Completed legacy jobs without revision, deletion epoch or object-generation binding fail closed.

Deletion requests atomically advance a denial generation and retain distinct pending job markers under the existing server-written `privacyRuntime/exportAuthority` path. Pending or failed legacy deletion jobs also deny. Cancellation/completion removes only its own pending marker, retaining the generation so previously published packages stay invalid after deletion/cancellation. No new consent grant or private-ingestion path is created.

These Spatial Functions no longer claim Privacy's canonical `getExportDownloadUrl`/`downloadExportPackage` names. Both current recent owner authentication and Auth token revocation are required; future, non-integer or non-number authentication times fail closed. The server rereads the same request/receipt, current consent revision, deletion generation and package deadline after Storage metadata and audits authorization before streaming. Every chunk (at most 64 KiB) repeats current authentication and authority checks; denial destroys the transfer before another chunk. Already emitted bytes cannot be recalled.

Native Capacitor origins have explicit bounded preflight support; literal native behavior remains unverified. Direct Storage client reads remain denied by existing rules. No new GCS signed URL is issued; old deployed signed URLs retain their original expiry/object-deletion transition and require live release accounting.

Export publication and its receipt commit atomically under current authority. A duplicate worker without a successful claim cannot delete a preparing worker's files. A successful but uncertain publication reply preserves committed bytes/receipt. Late cancellation/deletion is not overwritten by completion or failed-record resurrection.

The current job format bounds each portable collection to 500 documents and intelligence scenarios to 100, with bounded nested inventories. It now reads the next item and fails closed on overflow, including captured-runtime inventory growth during processing. It does not silently publish a truncated ready package.
