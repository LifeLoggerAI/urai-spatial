# UrAi protected private-runtime acceptance procedure

This procedure executes the existing consent, owner-media, export, withdrawal and deletion requirements. It is not a completed acceptance receipt. Bind every result to the final candidate SHA, preview fingerprint, Firebase project, deployed Functions/rules, account identities, time and reviewer. Keep opaque identifiers and private content in protected evidence.

Use a disposable protected staging owner and a second staging owner. Do not perform deletion tests on the founder's family account or production memories. Provider retention and permanent erasure require actual provider-policy evidence; a completed deletion request alone does not establish permanent erasure.

1. Confirm the preview and backend belong to the same requested candidate. Verify the genuine private bucket has uniform access and public-access prevention. Sign in and reauthenticate within five minutes. Record actual loaded Firebase configuration and server deployment identity without retaining credentials.
2. Use an owned memory, active canonical C1 `memory.storage` consent and fully enforced positive memory policy. Select it through Life Map → Focus. Attach an owned PNG/JPEG/audio/video at most 4MiB using the existing file control. Retain the actual source checksum, generation and opaque receipt privately.
3. Enter Replay and confirm it decodes the matching real bytes. Reload and traverse the return journey while preserving selection. A fixture or successful API schema check is not this result.
4. Separately grant C7 `data.export` and the current exports policy. In Privacy Controls request the memories export, wait for server-ready status and use Secure download. Compare exported media hashes with the source. Verify purpose, owner and current authorization at download.
5. Withdraw C1 or disable Replay through the genuine trusted control. Active media must stop and browser blob resources dispose. Old playback authority and affected export requests must deny access. Regrant only through the real consent flow, then verify a new generation can load without restoring stale authority.
6. A second owner and a signed-out browser must never obtain the first owner's media or private history. Exercise offline, token-expiry and interrupted/retried delivery on disposable data; inspect actual denials and recovery.
7. On staging-only disposable memories, choose Scoped deletion → CONFIRM DELETE → Create deletion request. Await actual server completion and disposal evidence, then refresh and verify old playback/export denies access. Inspect backup, cache and provider retention separately.
8. Using a disposable staging account, verify the existing 24-hour account-deletion grace period and cancellation. Capture actual account-state and backend readback rather than claiming permanent erasure from an accepted request.

These are source/control tests. No protected signed-in cloud session or family media was available to this execution lane, so native private acceptance remains open. Rerun the applicable source and runtime proofs after integration; do not transfer predecessor acceptance to a successor.
